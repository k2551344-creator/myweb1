# Supabase 테이블 만들기

이번 작업은 **데이터베이스 구조를 만드는 단계**입니다. 웹 앱 연결이나 실제 결제 연결은 별도 단계입니다.

## 지금 실행할 파일

1. `01_테이블생성.sql` — 최초 한 번 실행
2. `02_설치확인.sql` — 설치 후 확인할 때 실행 (반복 실행 가능)

SQL 안의 값을 수정하거나 비밀번호·API 키를 넣을 필요는 없습니다. 테이블을 하나씩 수동으로 만들 필요도 없습니다.

## 실행 방법

1. Supabase에 로그인하고 사용할 프로젝트를 엽니다. 이 프로그램 전용의 새 프로젝트를 사용하세요.
2. 왼쪽 **SQL Editor**를 열고 새 쿼리(**New query**)를 만듭니다.
3. 이 폴더의 **01_테이블생성.sql**을 열어 내용 전체를 복사합니다. 파일 이름만 복사하지 마세요.
4. SQL Editor의 쿼리 입력란에 붙여넣고 **Run**을 누릅니다.
5. 결과에 **SETUP_COMPLETE**가 표시되면 설치가 완료된 것입니다.
6. 새 쿼리를 하나 더 열고 **02_설치확인.sql** 전체를 붙여넣어 **Run**을 누릅니다.
7. 12개 확인 항목의 **result가 모두 PASS**인지 확인합니다.

SQL Editor가 선택한 부분만 실행하지 않도록, 입력란의 일부만 선택된 상태라면 선택을 해제한 뒤 실행하세요.

## 정상적으로 생기는 항목

- **public 스키마: 21개 테이블** — 회원, 센터, 관리자, 상품, 가격, 이미지 정보, 구독, 주문, 결제, 출석, 락카 등
- **gym_private 스키마: 2개 테이블** — 서버에서만 접근하는 결제 설정·빌링 참조
- **Storage: center-media** — 상품 사진과 배경 이미지 저장소 (5MB 이하 JPG/PNG/WebP)
- **RLS 권한 설정** — 본인·담당 센터의 데이터만 조회
- **회원 프로필 생성 설정** — Supabase Authentication에 사용자가 생성되면 profiles도 생성
- **가격 이력·일일 중복 출석·중복 락카 배정 등의 제약**

Table Editor에서는 기본 public 스키마의 21개 테이블이 보입니다. 비공개 테이블 2개는 스키마를 gym_private로 바꿔 확인할 수 있습니다. 실제 Secret Key는 이 테이블에도 직접 입력하지 않습니다.

회원과 센터가 아직 없어서 테이블 내용이 비어 있어도 정상입니다. 이미 Authentication에 사용자가 있었다면 그 사용자의 기본 프로필만 생성됩니다. 가상 회원·테스트 매출은 넣지 않습니다.

## 오류가 나오면

- **“같은 이름의 테이블이 이미 있습니다”**: 이미 설치했거나 다른 앱의 테이블이 있는 상태입니다. 기존 테이블을 삭제하지 마세요. 이전에 이 파일을 정상 실행했다면 02번 확인 파일만 실행합니다. 다른 앱의 테이블이라면 별도 프로젝트가 필요합니다.
- **“current transaction is aborted” / “25P02”**: 앞서 실패한 작업 때문에 이어서 실행할 수 없는 상태입니다. 새 쿼리에서 `ROLLBACK;`을 한 번 실행한 뒤, 최초 오류 내용을 확인하세요.
- **확인 항목에 FAIL 표시**: 그대로 중단하고 실패 항목과 오류 내용을 알려주세요.
- **그 외 오류**: 오류 문구 또는 화면을 알려주세요. Secret Key나 비밀번호는 필요 없습니다.

설치는 한 트랜잭션으로 처리됩니다. 도중에 오류가 생기면 이번 설치의 변경사항 전체가 취소됩니다. 기존 테이블을 지우는 명령은 없습니다. 이미 설치된 프로젝트에 반복 실행하면 초기 검사에서 중단합니다.

## 아직 하지 않아도 되는 것

- API 키 입력
- 회원·관리자 비밀번호를 SQL에 적기
- RLS 끄기
- gym_private를 Data API의 노출 스키마에 추가하기
- Storage를 공개 버킷으로 바꾸기

Storage는 비공개 버킷으로 만들되, 현재 판매 상품과 센터 배경에 연결된 사진은 조회 정책을 통해 보여줄 수 있게 설계했습니다. 담당 센터의 owner/manager만 업로드할 수 있고 staff는 업로드할 수 없습니다. 아직 관리자 배정이 없으므로 웹 업로드는 앱 연결·첫 관리자 등록 후 가능합니다.

## 다음 단계

1. 설치 결과와 확인 결과를 확인합니다.
2. 첫 센터와 관리자 계정을 등록합니다.
3. 웹 앱의 저장·로그인·사진 업로드를 Supabase로 연결합니다.
4. 센터·회원·상품·구독 작업을 인증된 서버 API에 연결하고 통합 검증합니다.
5. 웹에 배포한 뒤 휴대폰에서 확인합니다.

현재 웹은 여전히 테스트 저장소를 사용합니다. 이 SQL을 실행하는 것만으로 기존 화면이 Supabase를 사용하기 시작하지는 않습니다. 브라우저에서 결제·출석·회원권 정보를 임의 변경하지 못하도록 직접 쓰기 권한을 닫아 두었으며, 해당 쓰기 기능은 다음 단계에서 서버와 연결합니다.

## 검증 범위

PGlite 0.5.8의 PostgreSQL 엔진에서 실제 SQL을 실행하여 설치·RLS·외래키·금액·일일 출석·이미지 정책·재실행 방어 등 40개 검사를 통과했습니다. 테스트용 auth/storage 테이블로 Supabase의 기본 구조를 재현했습니다.

사용자님의 Supabase 프로젝트에는 아직 실행하지 않았습니다. 실제 Supabase Auth 서비스, Storage 업로드 서비스, 웹 앱과의 통합은 연결 후 추가 검증합니다.
