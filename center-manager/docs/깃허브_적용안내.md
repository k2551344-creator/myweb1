# 기존 GitHub Pages에 적용하기

이번 배포는 센터 정보·상품·상품 사진·회원 첫 화면 배경과 로그인 기능을 실제 Supabase에 연결합니다. 구독 구매·결제·QR 출석은 아직 연결하지 않았고, 공개 화면에는 센터 문의만 표시합니다. 기존 로컬 데모와 실제 DB를 쓰는 배포용 웹은 별도입니다.

## 1. 추가 SQL 실행

Supabase SQL Editor에서 `supabase/setup/03_웹연결추가.sql` 전체를 실행합니다. `CATALOG_API_READY`가 표시되면 성공입니다. 기존 테이블이나 데이터는 삭제하지 않습니다. 최초 설치용 01번 SQL은 다시 실행하지 마세요.

## 2. 인증 후 돌아올 주소 설정

Supabase의 Authentication → URL Configuration에서 Site URL을 다음으로 설정하고, Redirect URLs에도 같은 주소를 추가합니다.

https://k2551344-creator.github.io/myweb1/

이메일 가입과 이메일 확인을 사용합니다. 비밀번호는 웹의 가입 화면에 직접 입력합니다.

## 3. 준비된 파일 업로드

작업 폴더의 `깃허브_업로드` 폴더를 엽니다. 이 폴더 **안에 있는** `index.html`, `assets` 폴더, `.nojekyll`을 함께 업로드합니다. 폴더 이름 자체를 상위 폴더로 올리지 않습니다. ZIP을 사용한다면 먼저 압축을 풀어야 합니다.

1. https://github.com/k2551344-creator/myweb1 에 로그인합니다.
2. Add file → Upload files를 선택합니다.
3. 위의 세 항목을 함께 끌어다 놓습니다. `assets` 폴더 구조를 유지합니다.
4. Commit changes를 눌러 main에 반영합니다. 기존 index.html은 새 화면으로 교체됩니다.
5. Actions에서 Pages 배포 완료를 확인하고 기존 페이지를 새로고침합니다.

현재 Pages 배포 설정을 유지하면 됩니다. 설정을 확인해야 하는 경우 Settings → Pages에서 main 브랜치와 /(root)를 확인합니다. 전체 개발 폴더나 `.env.local`, SQL, node_modules는 업로드하지 않습니다.

## 4. 최초 관리자 등록

1. 배포된 페이지에서 로그인 → 계정 만들기를 누릅니다.
2. `taehwancoen@naver.com`으로 가입하고 도착한 인증 메일의 링크를 누릅니다. 이미 계정이 있다면 기존 계정으로 로그인합니다.
3. Supabase SQL Editor에서 `supabase/setup/04_최초관리자지정.sql`을 실행합니다. `ADMIN_READY`면 성공입니다.
4. 웹에서 관리자 → 권한 다시 확인을 누릅니다. 본점이 생성되어 있습니다.
5. 센터 정보에서 상호·전화·주소를 수정하고, 상품·사진과 회원 화면 꾸미기를 저장합니다.

04번은 이메일 인증이 완료된 지정 계정에만 권한을 줍니다. 이미 다른 센터가 있으면 중단하므로 오류 내용을 확인해 주세요. 공개 키만으로 관리자 권한을 만들 수는 없습니다.

## 적용 후 확인

- 로그아웃 상태에서 판매 중인 상품·사진·배경이 보이는지 확인합니다.
- 로그인 후 사진을 올리고 저장한 뒤 새로고침해 유지되는지 확인합니다.
- 가격을 수정한 뒤 다시 열어 새 가격을 확인합니다. 기존 가격 행은 유지됩니다.
- 상품의 신규 판매를 끄면 회원 화면에서 사라지는지 확인합니다.
- 사진 삭제 버튼은 상품/배경과의 연결을 해제합니다. 저장소 파일 자체를 지우지는 않습니다.

## 문제 해결

- `03_웹연결추가.sql` 안내: 03번 SQL을 실행하고 다시 확인합니다.
- 이메일 인증 뒤 다른 주소로 이동: 위 URL Configuration을 확인합니다.
- 가입 메일 발송 오류: Supabase의 이메일 발송 설정/제한을 확인해야 합니다. 오류 내용을 보내 주세요.
- 관리자 권한 없음: 이메일 인증 후 04번을 실행했는지 확인합니다.
- CSS/JS가 404: 저장소 루트의 index.html 옆에 assets 폴더가 있는지 확인합니다.

## 이번 검증

추가 DB API 23개, 초기 스키마 40개, 기존 업무 규칙 12개 검사를 통과했습니다. TypeScript 검사와 GitHub Pages 빌드도 통과했습니다. 실제 프로젝트에 03번 SQL이 아직 없는 상태에서 올바른 설정 안내가 나타나는 것과 로그인/가입 화면을 브라우저로 확인했습니다. 실제 이메일 인증·사진 업로드·저장과 GitHub 배포 완료는 위 적용 후 확인해야 합니다.

개발 시 `npm run build:pages`로 다시 빌드합니다. `.env.local`의 NEXT_PUBLIC_SUPABASE_URL과 NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY 두 공개 설정만 번들에 넣습니다. 관리자용 비밀 키는 사용하지 않습니다. 결과는 pages-dist에 생성됩니다.
